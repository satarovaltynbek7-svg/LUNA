# LUNA Café Django API

This service runs alongside the existing Express API. It shares the Render PostgreSQL database and maps the existing Prisma `MenuCategory`, `MenuItem`, `CafeOrder`, and `OrderLine` tables, so the existing owner dashboard and Django Admin see the same menu and orders. Django migrations do not recreate those Prisma-owned tables.

## Local setup

1. Install Python 3.11 or newer.
2. From the repository root, install the Django requirements:

   ```powershell
   python -m pip install -r backend\django_backend\requirements.txt
   ```

3. Configure `DJANGO_DATABASE_URL` in the root `.env`. It defaults to SQLite at `backend\django_backend\db.sqlite3`, which lets Django's health endpoint and admin run without PostgreSQL. Menu and order endpoints require the Prisma PostgreSQL tables; set `DJANGO_DATABASE_URL` to the same database as `DATABASE_URL` (without Prisma's `schema` query parameter) to use them.
4. Apply migrations and create a Django Admin account:

   ```powershell
   cd backend\django_backend
   python manage.py migrate
   python manage.py createsuperuser
   python manage.py runserver 8000
   ```

5. In another terminal, run the Vite website with `npm run dev`. The `/django-api` Vite proxy forwards requests to Django. Express continues to serve `/api` and requires its PostgreSQL database.

## API

- `GET /api/menu/` returns active categories and menu items using the frontend's existing multilingual response shape.
- `POST /api/orders/` creates an order. Send `customerName`, `customerPhone`, `address`, optional `tableNumber` / `note`, and `items: [{ "itemId": "latte", "quantity": 2 }]`. The server validates current menu items and recalculates the total from database prices; it never trusts a total supplied by the browser.
- `GET /api/health/` is the Render health check.
- `/admin/` is Django's staff-only admin. Create a Django superuser with `createsuperuser`; do not reuse the owner web-app credentials.

## Render deployment

The root `render.yaml` provisions a separate Python web service that shares the existing Render PostgreSQL database. The Django service runs the Prisma migrations before startup because Prisma owns the shared schema, then applies Django's own auth/admin migrations. Set `DJANGO_ALLOWED_HOSTS` to the Django service hostname and `CORS_ALLOWED_ORIGINS` to the exact public LUNA frontend origin. `DJANGO_SECRET_KEY` is generated by Render. Set `VITE_DJANGO_API_URL` in the frontend build environment to `https://<django-service-host>/api`; the local Vite proxy is only for development.

Deploy the existing Node service first when adding this backend to an existing production database, so its Prisma migration adds the nullable `CafeOrder.address` column before Django serves order requests. Django's app models are unmanaged mappings to Prisma tables; never run `makemigrations` to change those shared tables. Update `backend/prisma/schema.prisma` and add a Prisma migration for future shared-table changes.
